---
title: B608 SQL construction and CWE-89
cwe: CWE-89
source_url: https://cwe.mitre.org/data/definitions/89.html
---
Bandit B608 looks for SQL text assembled with string formatting, concatenation, or similar operations. This pattern maps to CWE-89 when untrusted input can change the structure of a query. The dangerous boundary is between SQL syntax and data: quoting a value by hand does not reliably preserve that boundary across encodings, database modes, and data types.

Use the database driver's parameter mechanism for every data value. Placeholder syntax varies by driver, so follow that driver's documented style and pass parameters separately from the SQL string. Parameters usually cannot stand for identifiers such as column names, table names, or sort directions. When an identifier must vary, map a small set of public choices to constant SQL fragments selected by trusted code.

Review helpers and ORM escape hatches as well as the flagged expression. Raw query methods, dynamically built filter clauses, and interpolated `ORDER BY` expressions can reintroduce the same weakness. A constant-only formatted query can be a false positive, but future edits may make it unsafe; replacing unnecessary formatting improves the design. Least-privilege database credentials and transaction limits reduce damage, yet they do not replace parameterization. Tests should include hostile punctuation to confirm it remains a value and cannot alter query structure.
