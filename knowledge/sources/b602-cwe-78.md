---
title: B602 subprocess shell execution and CWE-78
cwe: CWE-78
source_url: https://cwe.mitre.org/data/definitions/78.html
---
Bandit B602 identifies Python subprocess calls that enable a command shell, such as `subprocess.run(value, shell=True)`. This is relevant to CWE-78 because the shell gives special meaning to separators, redirections, substitutions, wildcards, and quoting. If any part of the command comes from a request, configuration file, repository content, or other untrusted source, an attacker may turn intended data into another command.

The strongest fix is to avoid the shell. Pass an argument list to `subprocess.run`, keep `shell=False`, and select the executable in trusted code. Validate values against the application's actual rules; an allowlist is useful when the value represents one of a small set of actions. Use an absolute executable path when the runtime environment cannot be trusted. Timeouts and a restricted service account reduce impact but do not remove command injection.

Do not treat `shlex.quote` as a universal repair. It is shell-specific, easy to apply at the wrong composition layer, and still leaves the program dependent on a shell. During review, trace every interpolated value to its source and check wrappers that assemble a command before reaching the flagged call. A constant command with `shell=True` may be lower risk, but removing the shell still produces clearer behavior.
